相対パスとは？ ../ の意味を読めるようになる

../を見たら「1つ上のフォルダへ戻る」と読みます。このサイトのファイルをたどりながら、画像やCSSまでの道順を読んでみましょう。

まず結論：../は1つ上へ戻る

記事のHTMLに、こんな指定があるとします。

<img src="../assets/koi.png" alt="">

「今いる場所から1つ上へ戻って、assetsフォルダの中にあるkoi.pngを読み込む」という意味です。ここでの「今いる場所」は、この指定を書いているHTMLファイルが置かれたフォルダと考えてください。

記号のかたまりに見えますが、やっていることはファイル探しです。まずは../を「上へ1回」と読めれば大丈夫です。

そもそも「パス」とは？

パスは、ファイルやフォルダの「住所」のようなものです。相対パスは、その住所を「今いる場所」を基準にした道順で表します。

英語から覚える：path

pathは英語で「道」「経路」という意味です。Web開発では「ファイルまでたどる道順」と考えると、記号の意味もつかみやすくなります。

このサイトのフォルダ構成を、今回使う部分だけ抜き出すと次のようになります。ほかの記事や設定ファイルは省略しています。

code-yomereba-ii/
├─ index.html
├─ assets/
│  ├─ styles.css
│  └─ koi.png
└─ articles/
   ├─ html-css-js.html
   ├─ if.html
   └─ href-src.html

トップページのindex.htmlと、assets・articlesの各フォルダが同じ階層にあります。記事はarticlesの中、画像やCSSはassetsの中です。

../を図で理解する

いまarticles/href-src.htmlを読んでいて、錦鯉の画像を読み込みたいとします。画像は別のフォルダにあるので、まずarticlesから1つ上へ戻ります。

articles/href-src.html
  │ 基準は articles フォルダ
  ↓ ../（1つ上へ）
code-yomereba-ii/
  ↓ assets/（中へ入る）
assets/
  ↓ koi.png（ファイルを選ぶ）
koi.png

この道順を続けて書いたものが、../assets/koi.pngです。

左から順番に読む

../ → 1つ上へ戻る
assets/ → assetsフォルダへ入る
koi.png → この画像ファイルを選ぶ

このサイトで使っているコードを読む

前の記事「hrefとsrcの違い」では、参照先と読み込み元を見ました。今度は、その中に書かれた「場所」に注目します。次の例は記事ページの指定を抜き出したもので、画像のクラスやサイズ指定、リンクの文言は説明用に簡略化しています。

CSSを参照する

<link rel="stylesheet" href="../assets/styles.css">

1つ上へ戻る → assetsへ入る → styles.cssを参照する。ブラウザが共通CSSを読み込み、ページの見た目に適用します。

画像を読み込む

<img src="../assets/koi.png" alt="">

1つ上へ戻る → assetsへ入る → koi.pngを読み込む。その画像がページ内に表示されます。

トップページへ移動する

<a href="../index.html">トップへ戻る</a>

1つ上へ戻る → index.htmlへ移動する。リンクをクリックすると、そのHTMLが開きます。トップページを指定しているのは、../に続くindex.htmlの部分です。

なぜトップページでは../が要らないのか

トップページのindex.htmlから見ると、assetsは同じ階層にあります。上へ戻らず、そのまま中へ入ればCSSに届きます。

<!-- トップページの index.html から -->
<link rel="stylesheet" href="assets/styles.css">

一方、articlesの中にいる記事から見ると、assetsは1つ上の階層にあります。

<!-- articles 内の記事から -->
<link rel="stylesheet" href="../assets/styles.css">

同じファイルを指定していても、今いる場所によって道順が変わります。CSSが2つあるわけではなく、出発地点が違うだけです。

記事の中でassets/styles.cssとだけ書くと、この構成ではarticles/assets/styles.cssを探してしまいます。そこにはファイルがないので、正しいCSSを読み込めません。

../../は2つ上へ戻る

../が1つ上なら、../../は2つ上です。「上へ戻る」を2回続ける、と読めます。

../       → 1つ上へ
../../    → 2つ上へ

さらに深いフォルダの中から戻るときに使います。まずは../の数だけ上へ戻る、と分かれば十分です。

./は今いるフォルダ

点が1つの./は「今いるフォルダ」を表します。次は、同じフォルダにphoto.pngがあると仮定した説明用の例です。このサイトに実在する画像ではありません。

<img src="./photo.png" alt="説明用の写真">

「今いるフォルダのphoto.pngを読み込む」と読めます。この例では、次のように./を省略しても同じ場所を指します。

<img src="photo.png" alt="説明用の写真">

HTMLではこのように省略できることが多いので、./をあまり見かけなくても不思議ではありません。点が1つなら「ここ」、2つなら「1つ上」です。

絶対的な指定との違い

次は説明用のURLです。場所を最初から全部指定する「絶対URL」の例で、このサイトの画像のURLではありません。

https://example.com/assets/koi.png

これなら、どのページから見ても指定先は同じです。一方、../assets/koi.pngは今いる場所を基準にするので「相対パス」と呼びます。

「絶対パス」は、基準となる最上位の場所から道順を指定する言い方です。Webでは/assets/koi.pngのように先頭を/にすると、サイトのドメイン直下が基準になります。フォルダの下で公開しているサイトでは、プロジェクトの先頭と一致するとは限りません。

今回は、「相対パスは出発地点によって読み方が変わる」という違いを押さえておけば大丈夫です。

エクスプローラーのフォルダ移動にたとえると

Windowsのエクスプローラーでarticlesフォルダを開いている、と想像してみてください。

  1. 「上へ」のボタンで、1つ上のフォルダへ戻る。
  2. assetsフォルダを開く。
  3. koi.pngを選ぶ。

この操作を文字にしたものが、../assets/koi.pngに近いイメージです。../assets/までなら、「上へ戻って、assetsを開く」という道順になります。

よくある勘違いは、この3つ

  • 「../は必ずトップページへ戻る」ではない。1つ上のフォルダを指すだけです。もっと深い場所なら、1つ上もまだ途中のフォルダです。
  • 「今いる場所」は、エディタで選択中のフォルダではない。ここまでのHTMLの例では、そのHTMLファイルの場所を基準に読みます。
  • ファイルを移動しても、同じ道順で届くとは限らない。記事を別の階層へ移すと、同じ画像でも相対パスの書き方が変わることがあります。
外部CSSでは、CSSファイルの場所が基準

別ファイルのCSS内に画像のurl(...)が出てきたら、基準はそのCSSファイルの場所です。HTML内のhref・srcと、外部CSS内の指定では、出発地点が違うことを覚えておくと迷いにくくなります。

href・srcと、道順を分けて読む

hrefやsrcは「何を指定しているか」、その値にあるパスは「どこにあるか」を表します。

<img src="../assets/koi.png" alt="">
  • src → 読み込み元を指定する属性。
  • ../assets/koi.png → そのファイルまでの道順。

「画像を読み込む。その場所は、1つ上のassetsの中」と分けて読めれば、記号を丸暗記しなくても意味を追えます。属性の役割は「hrefとsrcの違い」で振り返れます。

今日覚えること

pathはファイルまでの道順で、相対パスは今いる場所を基準にするため、同じファイルでも現在地によって書き方が変わります。

../は1つ上、../../は2つ上、./は今いるフォルダ、と読みましょう。
