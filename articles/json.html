JSONとは？ APIでよく使われるデータの書き方

JSONは、データを決まった形で書くための形式です。まずは「名前と値の組み合わせ」を読めれば大丈夫です。

APIから返ってきた結果を見ると、かっこや引用符が並んでいて難しく感じるかもしれません。 でも、「名前は何か」「その値は何か」と分けて読むと、内容をつかめます。 JSON（ジェイソン）は人にも比較的読みやすく、コンピュータ同士のデータ交換にも向いています。

キーと値：項目名と、その中身

次は、ある人の情報を表す簡単なJSONです。実行する手順ではなく、データそのものを書いています。

{
  "name": "Masa",
  "age": 31,
  "isChef": true
}

左側の "name" のような項目名をキー、 右側の "Masa" のような中身を値と呼びます。 表の「項目名」と「記入した内容」の組み合わせだと思うと読みやすくなります。

  • "name": "Masa"：名前はMasa。
  • "age": 31：年齢は31。
  • "isChef": true：「シェフである」が真、つまりシェフである。

これらのキーは、この例のデータに付けた名前です。JSONで必ず使う決まりの単語ではありません。 APIを読むときも、項目名の意味はそのAPIの説明に合わせて確認します。

名前の由来：JSON

JSONはJavaScript Object Notationの略です。

  • JavaScript：名前のもとになったプログラミング言語。
  • Object：ここでは、名前と値をまとめたデータのこと。
  • Notation：「表記法」、つまり書き表すための方法。

「JavaScriptのオブジェクトの書き方をもとにしたデータの表記法」と覚えられますが、JavaScript以外の言語でも使われます。

まず覚える記号は4つ

  • { }：名前と値を集めた、ひとまとまりのデータ。これをオブジェクトと呼びます。
  • [ ]：値を順番に並べた一覧。これを配列と呼びます。
  • :：左の名前と右の値を対応させます。
  • ,：項目と項目、または配列の値同士を区切ります。

最初の例では、外側の { } が1人分の情報をまとめています。 改行や字下げは読みやすくするためのもので、1行にまとめても同じデータを表せます。

文字や数字のほか、一覧や入れ子も扱える

JSONの値には、次のような種類があります。

  • 文字列："Masa" のような文字。二重引用符で囲みます。
  • 数値：31 や 24.5。引用符は付けません。
  • 真偽値：true（真）か false（偽）。「はい・いいえ」の判断を表します。
  • null：値がないことを表します。0や空の文字列とは別の値です。
  • 配列：["読書", "散歩"] のような一覧。
  • オブジェクト：{"city": "東京"} のような、名前と値のまとまり。

入れ子は「まとまりの中に、別のまとまり」

{
  "name": "Masa",
  "nickname": null,
  "hobbies": ["読書", "散歩"],
  "address": {
    "city": "東京"
  }
}

この例では、hobbies に趣味の一覧、address に住所のまとまりが入っています。 このように中へ別のデータ構造を入れることを「入れ子」と呼びます。 nickname の null は、この例ではニックネームが設定されていないことを表しています。

JSON全体が必ず { } で始まるわけではありません。 一覧を返す場合は [ ] が外側になることもあり、文字列や数値だけでもJSONとして表せます。

APIの結果としてJSONが返ってくるイメージ

APIに「天気を教えて」と依頼すると、結果がJSONで返ってくることがよくあります。 次は、気温を摂氏で返す天気APIを想定した架空の例です。 

{
  "weather": "sunny",
  "temperature": 24
}

weather は天気で、sunny は晴れ。 temperature は気温で、この例では24℃と読めます。 アプリはこの値を取り出して、画面に「晴れ・24℃」などと表示できます。

実際の項目名や温度の単位は、APIごとのルールで決まります。 APIの記事のたとえでいえば、APIが注文窓口、JSONは返ってきた情報の書き方です。 すべてのAPIがJSONを返すわけではありません。

JavaScriptのオブジェクトと、完全に同じではない

JavaScriptのオブジェクトは、プログラムの中で扱うデータのまとまりです。 JSONは、データを保存したり交換したりするための文字による表記形式です。 見た目は似ていますが、書ける内容やルールに違いがあります。

  • JSONでは、キーと文字列を必ず二重引用符 " で囲みます。
  • JSONでは、最後の項目の後ろに余分なカンマを付けません。
  • JSONには、コメント、関数、undefined は書けません。

例えば {name: 'Masa'} はJavaScriptのオブジェクトの書き方として使えますが、JSONではありません。 JSONなら {"name": "Masa"} と書きます。 JavaScriptやGASでは、JSONの文字列をデータに変換する JSON.parse()、 データをJSONの文字列にする JSON.stringify() が用意されています。 今は「扱うデータと、受け渡すための書き方を変換できる」程度の理解で十分です。

AIにJSONを説明してもらうときは

「各キーの意味と値の種類を説明してください」「このJSONから天気と気温を取り出したい」と伝えましょう。 キーの意味が分からない場合は、APIの説明も一緒に確認すると読み違いを減らせます。

今日覚えること

JSONは、APIなどでデータを受け渡すための書き方。まずは「キーは項目名、値はその中身」と読み、{ }はまとまり、[ ]は一覧と覚えましょう。
