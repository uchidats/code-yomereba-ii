Gitとは？ GitHubとは？ 変更履歴を残して安全に開発する仕組み

Git = 履歴を残す仕組み。
GitHub = その履歴を置いておくオンラインの場所。

AIにHTMLを直してもらったら、見た目が変わってしまった。前の状態と比べたい。 そんなとき、変更の記録があると原因を探したり、修正を取り消したりしやすくなります。 そのために使うのがGitとGitHubです。

Git：ファイルの変更履歴を残す仕組み

Git（ギット）は、ファイルの変更履歴を記録するための仕組みです。 「いつ、誰が、どんな変更を記録したか」を確認し、以前の状態と比較できます。 自分のPC上だけでも使えます。

Windowsの復元ポイントのように「戻るための区切りを残す」、 Wordの変更履歴のように「どこを直したかを確認する」と考えると、役割がつかめます。 ただしGitが扱うのは管理対象のプロジェクトのファイルで、PC全体を復元するものではありません。 キー入力をすべて自動記録するのではなく、残したい区切りで記録します。

GitHub：コードと履歴をオンラインで保存・共有する場所

GitHub（ギットハブ）は、Gitで管理したコードや履歴をオンラインに置き、共有できるサービスです。 別のPCから続きを作業したり、他の人に変更を見てもらったりできます。 GitとGitHubは同じものではありません。履歴を残す仕組みと、その置き場所の違いです。

手元の作業場所を「ローカル」、GitHubなどの接続先を「リモート」と呼びます。 ファイルを編集しただけでは、GitHubの内容まで自動で変わるわけではありません。

名前の由来：Git・GitHub

Gitの命名については、ここでは一つの由来や略語の展開を断定せず、仕組みの名前として覚えましょう。

GitHubは「Git + Hub」と分けると覚えやすくなります。Hubは「中心・集まる場所」という意味で、「Gitの履歴やコードが集まる場所」というイメージです。

repository：プロジェクト一式を管理する場所

repository（リポジトリ）は、プロジェクトのファイルと変更履歴を管理する場所です。 このサイトなら、HTMLやCSS、画像などをひとまとまりとして管理するイメージです。 ローカルのリポジトリと、GitHub上のリポジトリをつないで使えます。

commit・push・pull：記録する、送る、取り込む

commit：この時点の状態を記録する

commit（コミット）は、選んだ変更を「この時点の状態」として履歴に記録することです。 記録の前に対象の変更を選ぶ作業を「ステージング」と呼びます。 「トップページの見出しを変更」のような説明を添えると、後で何をしたか分かります。

ファイルの保存とcommitは別です。保存は編集中の内容をファイルに書き込み、commitは選んだ変更を履歴に残します。 commitしただけでは、まだGitHubへ送られていません。

push：ローカルの記録をGitHubへ送る

push（プッシュ）は、ローカルでcommitした履歴を接続先へ送ることです。 接続先がGitHubなら、手元で記録した内容がGitHub側にも反映されます。 commitしていない編集中の変更は、pushしても送られません。

pull：GitHub側の変更をローカルへ取り込む

pull（プル）は、接続先の履歴を取得し、ローカルの作業へ取り込むことです。 別のPCや共同作業者がGitHubへ送った変更を、自分の手元にも反映するときに使います。 同じ部分を別々に直していた場合は、どちらを残すか調整が必要になることがあります。

pushは「押し出す」、pullは「引き寄せる」という英語です。 「手元から送る」「手元へ取り込む」と方向で覚えると、混同しにくくなります。 どちらもGitの機能で、接続先はGitHub以外の場合もあります。

diff：変更前後の差分を見る

diff（ディフ）は、変更前と変更後の違い、つまり「差分」です。 例えば見出しを直した場合、次のように削除した行と追加した行で表せます。 

- <h2>最初に読む記事</h2>
+ <h2>まず読んでほしい記事</h2>

- は変更前にあった行、+ は変更後に加わった行です。 これは変更の見本で、HTMLへそのまま貼り付けるコードではありません。 AIに見出しだけを頼んだなら、関係のない本文やリンクまで変わっていないかを確認できます。

revert：記録済みの変更を打ち消す

revert（リバート）は、過去のcommitによる変更を打ち消す操作です。 通常は、元の履歴を残したまま「変更を打ち消す新しいcommit」を作ります。 「見出しを変更した」という記録に、「その変更を取り消した」という記録を追加するイメージです。

PC全体やプロジェクト全体を、無条件に昔へ戻す操作ではありません。 どのcommitを打ち消すかを選び、その後の変更と重なる場合には調整します。 未commitの編集を取り消す作業とも区別しましょう。

実例：HTMLを直してGitHubへ保存する

Gitで管理し、GitHubへの接続設定も済んだプロジェクトなら、次の流れで作業できます。

  1. CodexでHTMLを修正：「トップページの見出しだけを変更してください」のように、変えたい範囲を伝えます。
  2. diffで変更を見る：意図した行だけが変わっているか確認し、ブラウザでも表示を確認します。
  3. commitする：記録する変更を選び、「トップページの見出しを変更」などの説明を付けて履歴に残します。
  4. pushしてGitHubへ保存：commitした履歴を送り、GitHub側でも記録を確認します。

後で別の場所から変更された内容を受け取るときはpull、記録済みの修正を打ち消したいときはrevertを検討します。 AIに修正を任せても、差分を見て区切りごとに記録することで、何が変わったかを追いやすくなります。

今日覚えること

Git = 履歴を残す仕組み。GitHub = その履歴を置いておくオンラインの場所。

diffで確認し、commitで記録し、pushで送る。pullで取り込み、revertで記録済みの変更を打ち消します。
