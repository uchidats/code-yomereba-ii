Google Apps Script（GAS）とは？ Googleサービスを自動化する仕組み

GAS = Googleのサービスを自動で動かすためのJavaScript。まずは、このイメージが分かれば大丈夫です。

毎朝予定を確認する、メールの内容を表に転記する、ファイルを整理する。 Googleサービスで繰り返している作業を、コードに任せるための仕組みがGASです。 正確には、JavaScriptをベースにしたGoogleの開発環境で、コードを書く場所と実行する仕組みが用意されています。

名前の由来：GAS

GASはGoogle Apps Scriptの略です。

  • Google：この仕組みを提供している会社の名前。
  • Apps：Applicationsの略で、アプリやソフトウェアのこと。
  • Script：英語では「台本」。ここでは「比較的小さな処理を自動化するためのプログラム」というイメージです。

「Googleのアプリに、作業の台本を渡す」と考えると、役割を思い出しやすくなります。

ブラウザで書き、Google側で動かす

GASは、専用ソフトをPCにインストールせず、Googleアカウントでブラウザから使えます。 Apps Scriptでプロジェクトを作り、エディタにコードを書いて実行します。

Googleサービスを操作するスクリプトは、自分のPC上ではなくGoogle側で実行されます。 そのため、時間で動くトリガーを設定しておけば、PCを閉じていても処理を実行できます。 ブラウザは、コードを書いたり設定したりするための画面です。

よく見る4つの名前は、操作先の目印

GASには、Googleサービスを使うための機能が最初から用意されています。

  • GmailApp：Gmailのメールを検索したり、送信したりするためのもの。
  • CalendarApp：Google Calendarの予定を取得・追加するためのもの。
  • DriveApp：Google Driveのファイルやフォルダを扱うためのもの。
  • SpreadsheetApp：Google Sheets（スプレッドシート）のセルの値を読み書きするためのもの。

すべての使い方を暗記する必要はありません。 コードに CalendarApp が出てきたら「ここはカレンダーを操作する部分」と読めれば、理解の助けになります。

短い例：Google Calendarに予定を追加する

次の例は、自分の標準カレンダーに「GASの練習」という30分の予定を追加します。 日時は日本時間の2027年1月15日10時から10時30分です。試すときは、都合のよい日時に書き換えてください。 

function main() {
  const start = new Date("2027-01-15T10:00:00+09:00");
  const end = new Date("2027-01-15T10:30:00+09:00");
  CalendarApp.createEvent("GASの練習", start, end);
}

エディタに貼り付けて保存し、実行する関数として main を選んで実行します。 初回などにカレンダーへのアクセス許可が求められたら、内容を確認して許可します。 Google Calendarを開き、指定した日に予定が追加されていることを確認できます。

  1. new Date(...) で開始と終了の日時を用意します。+09:00 は日本時間を表す指定です。
  2. CalendarApp.createEvent に、予定名・開始日時・終了日時を渡します。
  3. Google側で処理され、標準カレンダーに予定が作られます。

このコードは実際に予定を追加し、実行するたびに新しい予定を作ります。 この例だけでは自動実行にはならず、手動で実行ボタンを押したときに動きます。 呼び出し方はGoogleの公式資料でも確認できます。

トリガー：いつ動かすかを決める

トリガーは、処理を開始する「きっかけ」です。 エディタのトリガー設定で、実行する関数ときっかけを選ぶと、自分で実行ボタンを押さなくても動かせます。

  • 時間をきっかけに：毎朝、今日の予定を一覧にする。
  • 編集をきっかけに：スプレッドシートの値が変更されたら処理する。
  • フォーム送信をきっかけに：回答を受け取ったら内容を整理する。

毎朝の実行は「9時台」のような時間帯の指定で、必ず9時00分ちょうどに動くとは限りません。 実行時間や利用回数にも上限があるので、まずは小さな作業から試すと理解しやすくなります。

「メールが来たら」は、定期的な確認で実現する

GASの標準トリガーには、Gmailの新着メール受信そのものをきっかけにする種類はありません。 「5分ごとにメールを確認し、新しい対象メールがあれば処理する」のように、時間のトリガーと組み合わせます。 同じメールを何度も処理しないよう、処理済みの目印を残すことも必要です。

APIとGASはどうつながる？

APIは、サービスの機能を使うための「窓口」と「決められた注文方法」でした。 GASは、その窓口へ依頼するプログラムを書き、動かす場所です。 先ほどの例なら CalendarApp.createEvent が、予定の追加を依頼するための呼び出し方です。

レストランにたとえると、APIは注文窓口、GASは決めた手順に従って注文する係です。 GASの組み込みサービスを使えば、自分で通信先のURLを書かずにGoogleの機能を利用できます。 また、外部のWeb APIへリクエストを送り、結果を受け取ることもできます。

Webアプリとして公開することもできる

GASは裏側の自動処理だけでなく、ブラウザで使うWebアプリとして公開することもできます。 例えば、入力画面から受け取った内容をスプレッドシートに記録する、小さな業務アプリを作れます。

この場合は、画面をHTMLなどで作り、Googleサービスを操作する処理をGASで書きます。 公開するときには、誰がアクセスできるか、誰の権限で処理を動かすかを設定します。 まずは「自動化だけでなく、操作画面も作れる」と覚えておけば十分です。

AIに頼むときは、作業ときっかけを伝える

「毎朝、今日のカレンダーの予定を取得してスプレッドシートに書き出したい」のように、 いつ・どのサービスから・何を取得して・どこへ渡すかを伝えましょう。 「必要なアクセス許可とトリガーの設定方法も説明して」と添えると、動かすまでの手順が分かります。

今日覚えること

GAS = Googleのサービスを自動で動かすためのJavaScript。ブラウザで書き、Google側で動かし、トリガーで実行のきっかけを決められます。
