非エンジニアがAIとCodexで1日でWebサイトを公開した記録

ほぼ初心者の私でも、AIに相談し、作って、直すことを繰り返して、1日でこのサイトを公開できました。完成品というより、これから育てられるサイトの土台を作った記録です。

1. きっかけは「コードは読めればいいのでは？」

コードを全部自分で書けなくても、書いてあることを少し読めれば、AIと一緒に開発できるのではないか。そんな考えが、このサイトを作り始めたきっかけでした。

ちょうどCodexに興味を持ち、ChatGPTと相談しながら、実際にサイトを作ってみることにしました。分からない言葉を自分用に整理して、それが同じような初心者にも役立ったらうれしい。まずは、そのくらいの気持ちでのスタートです。

2. 開始時点は、ほぼ初心者

最初から道具を使いこなせたわけではありません。開始時点の私は、こんな状態でした。

  • HTML・CSS・JavaScriptの違いを、少しずつ理解し始めた程度。
  • GitやGitHubの経験はほとんどない。
  • Codexも使い始めたばかり。
  • Webサイトをゼロから公開した経験もほぼない。

全部勉強してから始めようとすると、いつまでも準備中になりそうです。そこで、作りながら必要なことだけ覚える方針にしました。分からない単語は、その場で聞く。まずはそれで進めてみよう、と。

3. まずはChatGPTで設計を相談

最初に相談したのはコードよりも、「何のためのサイトにするか」でした。目的、タイトル、カテゴリ構成、記事の流れ、デザインを、ChatGPTとのやり取りで少しずつ決めました。

目指したのは、プログラマーになるための本格的な教科書ではなく、AIにコードを書いてもらいながら、その意味を最低限追えるようになる場所です。自分がつまずいた言葉を、未来の自分にも分かるように残したいと思いました。

サイト名は「コードは読めればいい。たぶん。」。私自身まだ確信があるわけではありませんが、きっと同じように考えている人は多いはずですし、これからそんな世界になっていくのではないか、という期待も込めて「たぶん。」を付けました。堅苦しくなりすぎず、このサイトにはちょうどいい名前になった気がします。

4. VS CodeとCodexで、実際のファイルを作る

方向が見えてきたら、ファイルを編集するための道具、VS Codeでプロジェクトのフォルダを開き、Codexに作成や修正を頼みました。

特に便利だったのは、ChatGPTのコードをコピーしてVS Codeへ貼り付け、修正版をまたコピーして相談する往復が、大幅に減ったことです。ファイルが増えると、「今コピーしたのは、どの記事のどの版だっけ？」だけでも迷子になれます。

Codexには、複数のHTMLや共通のCSSを直接確認し、必要な箇所をまとめて修正してもらえました。「スマホのときだけ表示を変えて」「リンク先はそのままで」と、やりたいことを言葉にして伝えられるのも助かりました。

ただ、頼んで終わりではありません。変更された箇所を見て、ブラウザで開き、思っていた表示と違えばまた相談する。その繰り返しでした。私にとっては、ChatGPTで方向を相談し、Codexで実際のファイルを直す流れが使いやすかったです。

5. GitとGitHubで、変更を記録して送る

ファイルを作るだけでなく、変更の記録も残そうとGitを導入しました。最初はGitとGitHubの名前が似ているだけで混乱しましたが、Gitは手元の変更履歴を管理するもの、GitHubはそのファイルや履歴をオンラインに置く場所、と考えると整理できました。

commitは、私の感覚では「復元ポイント＋変更履歴」のようなものです。選んだ変更を「ここまでできた」と記録する操作で、ファイルの保存とは別でした。そして、その記録をGitHubへ送るのがpush。commitしただけでは、まだ手元にある。この違いも、使いながら覚えました。

言葉を先に暗記するより、「直したものを記録する」「それを送る」と、今やりたい作業と結び付けた方が、私には分かりやすかったです。

6. GitHub Pagesで、スマホから開けるサイトに

GitHubへ送ったHTMLサイトは、GitHub Pagesを使ってインターネット上に公開しました。GitHubにファイルを置くことと、Webサイトとして公開することは別で、公開のための設定も進めました。

それまで自分のPCの中で見ていたページが、公開したURLをスマートフォンで開くと表示される。「あ、本当に外から見られるんだ」と、ちょっと驚きました。仕組みとしては当然なのかもしれませんが、自分で作ったものだと、うれしさが違います。

7. 当然、途中ではいろいろ失敗した

ここまで書くと順調そうですが、実際には立ち止まる場面もありました。専門家なら当たり前かもしれないことが、初心者には全部新鮮です。できれば平穏に新鮮さを味わいたかったのですが。

  • Gitの「同期」が、くるくるしたまま止まる。待てばいいのか、何か間違えたのか分からない。画面は動いているのに、こちらの作業は止まりました。
  • amendで履歴が分岐する。直前のcommitを作り直す操作（コマンドではgit commit --amend）を使ったら、GitHubへ送ってあった履歴と手元の履歴が分かれました。「少し直す」つもりが、履歴の仕組みを学ぶ時間になりました。
  • git push --force-with-leaseを初めて使う。作り直した履歴を送る場面で出会いました。接続先の履歴が想定どおりかを確認して強制更新する指定で、同期が止まるたびに使うものではない、と覚えました。
  • スマホ表示が直らない原因は、キャッシュ。修正したはずなのに変わらず、コードを疑っていたら、ブラウザが前のデータを保存して表示していました。直っていないのではなく、古いものを見ていたわけです。
  • ホーム画面のアイコンにもサイズがある。192px、512px、180pxの画像を用意しました。錦鯉を1枚置けば終わり、と思っていたら、サイズ違いの錦鯉も必要になりました。
  • PWAとしてのアプリ化も試す。Webサイトをアプリのように使う仕組みにも手を伸ばしましたが、まずはホーム画面から開くショートカットで十分、と判断しました。やれることを全部やると、肝心の記事を書く時間がなくなりそうです。

どれも最初から分かっていたことではありません。起きたことをChatGPTやCodexに相談し、言葉の意味を調べて、一つずつ進めました。つまずいた分だけ、「次に同じことが起きたら、ここを見よう」が増えた気がします。

8. 1日で、育てられるサイトの土台まで

この日は、次のところまで進められました。

  • トップページと複数の記事、カテゴリページ。
  • 読む順番を示す学習ロードマップと、新着記事の一覧。
  • 分からない言葉や書き方を探す、用語索引とコード索引。
  • スマホ対応と、錦鯉のアイコン。
  • GitHub Pagesでの公開。

「1日で完成した」と言い切ると、少し違います。記事も増やしたいですし、使いながら直したい場所もあります。1日で“育てられるサイトの土台”まで作れた、というのが実感に近いです。

AIが一度の指示ですべて仕上げてくれたわけではなく、私も目的を考え、表示を確認し、修正をお願いしました。今回はこの規模のサイトでここまで進められた、という記録であって、どんなものでも1日で作れるという話ではありません。

9. やってみて分かったこと

AIのおかげで、Webサイトを作るハードルはかなり下がったと感じました。コードを全部暗記して、自分の手だけで書けるようになるまで待たなくても、作り始められます。

一方で、コードを全く読めない状態より、最低限でも意味を追える方が圧倒的に楽でした。「これはリンク先」「ここは見た目の指定」と分かるだけで、AIに頼む内容も、修正後に確認する場所も、少し具体的になります。

AIの出力を確認するときも、読めることには価値がありました。お願いしていない場所まで変わっていないか。意図したページへつながるか。全部を理解できなくても、見る手がかりがあるだけで違います。

分からない用語が出たら、その場で調べればいい。今回つまずいた言葉も、これからこのサイトの記事や索引にしていこうと思っています。自分のためのメモが、誰かの「これなら自分にもできるかもしれない」につながればうれしいです。

今日覚えること

AIと作りながら、必要な言葉とコードの意味を少しずつ覚えていけばいい。全部書けなくていい。でも、読めると強い。
