APIとは？ アプリ同士をつなぐ窓口

APIは「窓口」と「決められた注文方法」。相手の仕組みを全部知らなくても、用意された機能を使えます。

「カレンダーから予定を取得する」「Gmailの情報を読み取る」。 こうした連携では、別のサービスが持つ機能をコードから使います。 そのときの窓口とやり取りのルールがAPIです。

APIはレストランの注文窓口のようなもの

レストランの厨房に自分で入る必要はありません。
メニューを見て、店員に決められた方法で注文すれば料理が出てきます。

APIも同じです。相手の内部構造を知らなくても、決められた方法で依頼すれば、機能を利用して結果を受け取れます。 アプリやサービス同士がやり取りするための「窓口」と考えると分かりやすくなります。

  • メニュー：利用できる機能を説明したAPIの資料。
  • 注文方法：依頼先や、渡す情報の名前・形式などのルール。
  • 注文と料理：送る依頼と、受け取る結果。

料理の作り方を知らなくても注文できるように、データの保管方法などを知る必要はありません。 ただし、メニューにない料理を注文できないのと同じで、APIが用意している機能とルールを確認する必要があります。

名前の由来：API

APIはApplication Programming Interfaceの略です。

  • Application：アプリやソフトウェアのこと。
  • Programming：プログラムを書くこと。
  • Interface：もの同士が接する部分や、やり取りするための接点。

まとめると「プログラムからアプリの機能を使うための接点」と覚えると、役割がつかめます。

GASでもGoogleサービスの機能を呼び出している

Google Apps Script（GAS）には、Googleサービスをコードから使うための窓口が用意されています。 Google Calendarなら CalendarApp、Gmailなら GmailApp、 Google Driveなら DriveApp です。

これらの組み込みサービスを使うと、予定を取得したり、メールやファイルを扱ったりできます。 Googleの内部のプログラムを書き換える必要はなく、用意された呼び出し方に従って機能を使います。

GASの例：Gmailの未読スレッド数を調べる

受信トレイにある未読スレッドの数を、実行ログに表示してみましょう。 スレッドとは、返信などでつながったメールのまとまりです。この例はメールの送信や削除は行いません。 

function main() {
  const count = GmailApp.getInboxUnreadCount();
  Logger.log(count);
}

GASのエディタに貼り付けて保存し、実行する関数として main を選んで実行します。 初回などにGoogleアカウントへのアクセス許可が求められたら、内容を確認して許可します。 実行ログには、自分の受信トレイの未読スレッド数が表示されます。例えば3件なら 3 です。

  1. GmailApp.getInboxUnreadCount() で、Gmailの窓口に未読スレッド数を問い合わせます。
  2. 返ってきた数を count という変数に入れます。
  3. Logger.log(count) で、数を実行ログに表示します。

ここで大切なのは、Gmailの内部構造を知らなくても、決められた呼び出し方で情報を取得できることです。 呼び出し方と返される値は、Googleの公式資料で確認できます。

Web APIでは、URLに依頼して結果を受け取る

Web APIでは、インターネットなどを通じて、決められたURLに依頼を送ります。 この依頼を「リクエスト」、返ってくる応答を「レスポンス」と呼びます。 URLは注文先の住所、リクエストは注文、レスポンスは返ってくる結果に当たります。

結果はJSON形式で返されることが多くあります。 JSONは、{"count": 3} のように、項目名と値を決まった書き方で表すデータ形式です。 この例なら「countという項目の値が3」と読めれば十分です。

先ほどのGASの例は、組み込みサービスがやり取りを扱うため、自分でURLやJSONを書く必要はありません。 APIにはいろいろな使い方があり、すべてがURLへの依頼やJSONの受け取りになるわけではありません。

APIキーや認証が必要な場合もある

APIによっては、利用するアプリなどを識別する「APIキー」という文字列が必要です。 また、個人のメールや予定を扱う場合などには、誰が使うかを確認する認証や、アクセスの許可が必要になります。 レストランで会員証や本人確認を求められる場面をイメージすると分かりやすくなります。

GASの例で出てくるGoogleの許可画面も、そのための仕組みです。この例では自分でAPIキーを用意する必要はありません。 必要な手続きはAPIごとに違うので、まずは「利用前に鍵や許可が必要な窓口もある」と覚えておきましょう。

AIにAPIの利用を頼むときは

「Gmailから未読スレッド数を取得したい」のように、使うサービスと目的を伝えます。 「どの窓口を使い、何を渡し、何が返るか。必要な認証も説明して」と添えると、コードの意味を理解しやすくなります。

今日覚えること

APIは、アプリ同士をつなぐ「窓口」と「決められた注文方法」。相手の内部構造を知らなくても、ルールに従って依頼すれば機能を使えます。
